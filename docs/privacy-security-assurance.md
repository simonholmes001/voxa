# Voxa Privacy and Security Assurance Baseline

Status: draft assurance baseline for MVP and App Store readiness.
Owner: Codex.
Related issue: #85.
Last reviewed: 2026-09-15.

This document records the current evidence-backed privacy, data handling, and
security posture for Voxa. It is not legal advice. It is the engineering
control baseline used to decide what must be fixed before App Store submission
and broader testing.

## Scope

Voxa is an iPhone/iPad language tutor backed by Azure Functions, Azure Storage,
OpenAI APIs, Apple Sign in, and TestFlight/App Store distribution.

In scope:

- iOS app storage, permissions, privacy manifest, and App Store disclosures.
- Backend authentication, learner state, AI calls, logs, and telemetry.
- Azure infrastructure controls in Bicep.
- GDPR-style data inventory, retention, user rights, and processor evidence.

Out of scope for this baseline:

- Legal approval of the final privacy policy.
- Production Data Protection Impact Assessment sign-off.
- Paid subscription entitlement policy.

## Official Requirements Checked

Apple requirements are tracked from official Apple Developer sources:

- App Review Guidelines, especially 5.1 Privacy.
- User Privacy and Data Use.
- App Store Connect App Privacy details.
- Privacy manifest files.
- Required reason API declarations.
- Account deletion requirement for apps with account creation.

GDPR posture is assessed against the core principles of lawfulness,
fairness/transparency, purpose limitation, data minimisation, accuracy, storage
limitation, integrity/confidentiality, and accountability.

## Current Security Controls

Verified in repo:

- iOS tokens use Keychain generic-password storage with
  `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`.
- Permanent OpenAI API keys are backend-only and loaded through Key Vault
  references in Azure deployment.
- Realtime clients receive short-lived OpenAI client credentials rather than the
  permanent API key.
- Backend access tokens are HMAC-signed, expire, and are validated before
  authenticated endpoints access learner state.
- Refresh tokens are random and stored by hash-derived row key, not raw token.
- Learner state uses explicit tenant/user scope and optimistic versions.
- Azure Storage disables blob public access and shared-key access, requires
  HTTPS, and defaults to OAuth authentication.
- Key Vault has RBAC authorization and soft delete enabled.
- Function App uses managed identity and Key Vault references.
- Log Analytics and Application Insights retention are configured to 30 days.

Not yet fully evidenced:

- Runtime Azure configuration after deployment matches Bicep defaults.
- All OpenAI paths avoid logging raw upstream bodies or generated learner
  content; this branch redacts the older course-author, learner-plan, debrief,
  and realtime client-secret failure paths.
- Account deletion removes learner state, refresh sessions, realtime audit
  rows, and realtime rate-limit rows for the authenticated subject.
- App Store Connect App Privacy answers match actual app behavior.
- Processor/subprocessor and international-transfer records exist.

## App Store Privacy Baseline

The iOS privacy manifest declares:

- No tracking and no tracking domains.
- User ID, other user content, audio data, photos/videos, product interaction,
  and diagnostic data as collected data categories.
- Data is marked linked to the user and not used for tracking.
- UserDefaults access with reason `CA92.1`, because the app writes
  app-specific onboarding draft and tutor preference values.

This is intentionally conservative for the MVP. Before App Store submission,
generate Xcode's privacy report and reconcile it with App Store Connect App
Privacy answers.

Required App Store work before submission:

- Publish a privacy policy URL and expose it in-app.
- Add an in-app account deletion initiation path.
- Confirm the App Privacy answers cover Apple Sign in identifiers, learner
  profile, generated course content, voice/audio, transcripts, translation
  images, diagnostics, and third-party processing.
- Confirm bundled third-party SDK privacy manifests are present and accurate.
- Confirm permission copy for microphone, speech recognition, camera/photo
  library, and notifications is specific to Voxa's feature use.

## Logging and Telemetry Rules

Backend and iOS logs must not contain:

- Auth tokens, refresh tokens, Apple identity tokens, or authorization codes.
- Permanent OpenAI API keys or short-lived Realtime client secrets.
- Raw OpenAI request/response bodies.
- Learner free text, translated text, transcripts, uploaded image text, or
  generated sensitive content.
- Full tenant/user identifiers unless a specific operational reason exists and
  the value is hashed or otherwise minimized.

Allowed by default:

- Status codes, endpoint names, byte counts, correlation IDs, error classes,
  model route identifiers, and bounded counts/durations.

Secure debug logging, if ever added, must be explicitly gated by environment,
disabled in production, time-limited, and redacted.

## Follow-Up Work Required

These are implementation issues, not documentation nice-to-haves:

1. Publish the final privacy policy URL and configure
   `VOXA_PRIVACY_POLICY_URL` for TestFlight/App Store builds.
2. Add retention controls for learner state, debrief evidence, realtime audit,
   rate-limit rows, and generated course content.
3. Add App Store Connect privacy-answer checklist and reviewer notes before
   first external submission.
4. Validate deployed Azure resources against Bicep security expectations.

## Release Gate

Before external TestFlight expansion or App Store submission:

- Privacy policy URL exists and matches this inventory.
- App Store Connect App Privacy answers are completed from this inventory.
- `PrivacyInfo.xcprivacy` is reviewed against Xcode's generated privacy report.
- Account deletion is implemented and verified against deployed storage.
- Raw learner-content logging is removed or proven absent across AI paths.
- Retention/export/deletion follow-up issues are either complete or accepted as
  a documented MVP residual risk by the owner.
